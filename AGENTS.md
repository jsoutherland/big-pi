# Maintainer guidance

- **Purpose:** Maintain big-pi as a standalone Pi extension. Do not add Pi-vot-specific integration, search, embeddings, external services, or unrelated features without an explicit task.
- **Clean room:** Use only the public Pi APIs and original implementation in this repository. Do not copy code from external clean-room reference implementations.
- **Scope:** Tier 3 is the supported maximum. No Tier 4 or new compression algorithm is implied.
- **Transcript and storage:** Never rewrite/delete Pi's original JSONL transcript. Persist default state in `<session>.jsonl.big-pi/`; when `BIG_PI_AGENT_ID` is set, persist that agent’s state in `<session>.jsonl.big-pi-agents/<sha256-agent-key>/`. versioned `manifest.json` plus immutable `blocks/` chunks. The manifest owns session identity, stable refs, block index/relationships/lifecycle, metrics, and recovery state; each chunk owns its summary and source provenance. Write/validate chunks before atomically replacing the manifest, never overwrite committed chunks, and never migrate the previous single-sidecar format. Preserve committed damaged entries during local fallback; untrusted manifests/session identity fail open.
- **Agent cleanup API:** Export `deleteBigPiAgentData(sessionPath, agentId)` and `deleteAllBigPiAgentData(sessionPath)` from the package entry point so other extensions can clean scoped data without knowing internal paths.
- **Compression:** Compression is model-driven: the active agent chooses semantic ranges and writes summaries. Do not add a hidden summarizer or automatic range selection.
- **Representation/provenance:** For each source range, emit exactly one highest applicable representation. Respect stable lineage, supersession, branch/projection applicability, fingerprints, and protection rules; dormant/inapplicable history remains intact.
- **Failure behavior:** Fail open to original context and Pi-native compaction when state or transformation cannot be trusted. Transient projection mismatches must not poison later requests.
- **Compaction ownership:** Use Pi's supported `session_before_compact` hook and `{ cancel: true }`; intercept while big-pi is healthy and explicitly yield to Pi for unsafe/exhausted emergency fallback. Do not fabricate replay behavior.
- **Runtime/package:** Keep third-party runtime dependencies at zero. The local Pi package declares its executable JavaScript entry in `package.json` under `pi.extensions`; release output must not require target-side npm installation or TypeScript compilation.
- **Pi APIs:** Preserve supported extension APIs used by the implementation, including `registerTool`, `registerCommand`, `sendUserMessage`, `context`, `before_agent_start`, compaction lifecycle events, `sessionManager` projection/tree APIs, and `getContextUsage`.
- **Validation:** Run `npm test`, `node --check index.js`, `node --check lib/big-pi.js`, and `git diff --check`. Packaging changes must also pass packaging tests and release verification. Do not claim a live Pi smoke test unless it was actually run.
- **Documentation:** Keep user instructions in README/START_HERE/docs and maintainer-only policy here. Document behavior from current code, not planned settings or assumed Pi versions.
- **Task tracking:** Update `TASK.md` while implementing changes. It remains source-repository development material and is excluded from releases.
